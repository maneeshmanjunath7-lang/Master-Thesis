## Repair-specific code changes

The physical model, random seed, scenario construction, routing logic, failure
models, storage policy, and scientific parameters are unchanged. The package
adds only orchestration and integrity controls:

1. strict task-file and allow-list SHA-256 checks;
2. an explicit case allow-list applied before worker creation;
3. India-only execution into a new output root;
4. per-case recording of task and allow-list hashes;
5. corrected selected-case estimates and status counts;
6. protected-path checks preventing use of the original campaign output name;
7. post-run verification of all 282 cases and all 539 scenarios per case; and
8. a verified export command for returning the corrected layer from the VM;
9. exact equality between all 773 filtered and normalized India task IDs;
10. normalized-task, case-plan, scenario-plan, and whole-run SHA-256 contracts;
11. rejection of old 741-task partitions before resume can skip any scenario;
12. strict partition checks for corruption, duplicate scenarios, wrong case IDs,
    and unfinished statuses; and
13. a mandatory verified one-case canary before the full run can start.
