# Final corrected India 282-case run for the Ubuntu VM

This package reruns only the 282 audited India cases that must use the complete 773-task population. It is intentionally independent of the earlier campaign directory.

## What was actually wrong

The original regional filter retained the India rows with source indices 32–804. The normalizer constructed a new 0–772 table, and pandas aligned columns by index labels. That discarded the final 32 India tasks and produced 741-task outputs.

The first repair reset the regional index and checked the resulting count, but its resume logic still trusted existing scenario partitions when the raw CSV hash matched. Both the incorrect and corrected runs use the same 805-row CSV, so a resumed run could silently keep old 741-task checkpoints. This package closes that second failure mode.

## Safety controls in this version

- The filtered India task IDs must match all 773 normalized task IDs exactly.
- Both the task-ID set and the complete normalized task table receive SHA-256 fingerprints.
- Every output root, case manifest, success marker, and scenario plan is tied to one immutable run-contract hash.
- A 741-task case manifest or any output from a different contract is rejected before workers start.
- Corrupt partitions, duplicate scenarios, wrong case IDs, and unfinished checkpoint statuses abort resume.
- A mandatory one-case canary must complete and pass verification before the 282-case command is allowed to start.
- The final verifier checks 282 cases × 539 unique scenarios, requires every task-metric scenario that should be retained, rejects missing or duplicated retained scenarios, and validates each group against all 773 task IDs.
- The main output root is new: `outputs/india_282_corrected_773_tasks_vm_contract_v2`.
- Package verification distinguishes immutable source files from `.egg-info` metadata generated by the editable installation, and setup performs a second integrity check after installation.
- The background-process PID is stored under `logs/`, so starting the run cannot make the immutable-package check fail.

Do not copy an old `outputs` directory into this package. Keep previous runs separately for audit.

## VM installation

Copy the ZIP to the Ubuntu VM, open a terminal in its parent directory, and run:

```bash
unzip Full891_India_282_VM_Final_Fixed_20260928_v4.zip
cd Full891_India_282_VM_Final_Fixed_20260928_v4
bash SETUP_VM.sh
bash PREFLIGHT_282_VM.sh
```

The preflight must say `PASS` and show:

- 282 selected cases;
- 539 scenarios per case;
- 773 normalized India tasks;
- 773 unique normalized task IDs; and
- a non-empty run-contract hash.

## Mandatory canary

Before the long run:

```bash
bash RUN_CANARY_VM.sh
```

This runs one audited 180-satellite/CN30 case with the 11-scenario smoke plan. Do not continue unless it ends with `Canary PASS`.

## Start and monitor the final run

```bash
bash START_282_BACKGROUND_VM.sh
bash STATUS_282_VM.sh
```

The configuration requests up to 16 workers. The runner selects the smaller of 16, the available logical CPUs, and the RAM-safe worker count. With approximately 30 GB RAM, 16 workers require at least about 25.6 GB available at launch after reserving 4 GB for Ubuntu. Close VS Code, browsers, and System Monitor before starting if you want all 16 workers. If less memory is available, the runner automatically uses fewer workers rather than swapping heavily.

The four numerical libraries are restricted to one thread per worker, preventing hidden BLAS oversubscription.

## Resume after interruption

Run the same start command again:

```bash
bash START_282_BACKGROUND_VM.sh
```

Only checkpoint partitions whose case, task, scenario, and run-contract fingerprints match are reused. An incompatible checkpoint stops the run with `INCOMPATIBLE RESUME DATA`; it is never silently accepted.

## Final verification and export

The run script verifies automatically. You can repeat it with:

```bash
bash VERIFY_282_VM.sh
```

Accept the results only if `verification_282.json` reports:

- `status: PASS`;
- `verified_complete_cases: 282`;
- `missing_or_invalid_cases: 0`;
- `scenario_count_per_case: 539`; and
- `task_count_india: 773`.

Create the archive to copy back to the laptop:

```bash
bash EXPORT_282_VM.sh
```

The archive will be named `india_282_corrected_773_tasks_vm_contract_v2.zip`.
